# Markdown 編輯器：稽核與優化紀錄

更新日期：2026-08-06

## 原本的限制

1. `.md` 檔案是由網頁編輯器寫出的副本；使用者在資料夾中修改後，沒有明確的載入、比較或下載流程，下一次網頁儲存可能覆蓋外部修改。
2. 每次變更各自發出儲存請求。網路延遲不同時，較舊請求可能晚於新請求完成，造成資料庫與 Markdown 檔案短暫不一致。
3. 編輯器只有粗體、斜體、底線、清單、待辦、表格、連結與子頁面。標題、引用、程式碼、編號清單、刪除線、復原／重做仍要靠快捷鍵或 Markdown 匯入。
4. 檢視者可以在畫面中嘗試編輯，雖然伺服器會拒絕，但使用體驗會讓人誤以為內容已寫入。
5. 寫入檔案不是原子操作；備份或其他程式在寫入中讀檔時，理論上可能讀到半份內容。
6. Markdown 與 Tiptap 的模型不是一對一。資料庫、複雜表格、巢狀任務、附件、留言、版本歷史與即時協作屬於工作空間資料模型，不會完整變成標準 Markdown。
7. Yjs 協作伺服器目前是記憶體型態。服務重啟時未完成資料庫儲存的即時更新沒有持久化保證；多個協作伺服器也不能直接水平擴充。

## 本次已完成

- 加入 **Markdown 原始碼模式**：可查看、複製、修改並套用 Markdown；套用內容會轉成協作區塊並進入正常儲存流程。
- 加入 **讀取檔案** 與 **下載 `.md`**：讀取會要求確認後才以專案資料夾中的檔案覆蓋編輯器；下載保留 YAML front matter。
- 儲存改為單一序列佇列：連續輸入僅保留最新快照，避免同一瀏覽器中的請求亂序覆寫；網路錯誤會保留待送內容並在下次儲存循環重試。
- 寫入 `.md` 改為暫存檔再原子更名，避免產生半份檔案。
- 工具列補齊標題、刪除線、編號清單、引用、程式碼區塊、復原與重做。
- 檢視者會進入真正的唯讀模式；無法更名、編輯、套用 Markdown、建立子頁面、留言或還原版本。
- 新增受權限保護的 Markdown API：`GET /api/documents/:id/markdown`，加上 `?download=1` 可下載原始檔。

## 協作核心升級（2026-08-06）

- Yjs 協作伺服器改為掛載持久化磁碟，服務重啟後會從協作文件資料庫恢復未寫入 PostgreSQL 的即時更新。
- 瀏覽器使用 IndexedDB 保留 Yjs 本機狀態；短暫離線後重新連線時，由 CRDT 自動合併，不以最後寫入者覆蓋其他人內容。
- 加入協作游標與選取範圍，並在文件下方顯示在線協作者數量。
- 協作模式停用 StarterKit 原本的本機歷程，改用 Yjs 的多人復原／重做歷程，避免將他人的最新變更誤復原。
- 檢視者不再取得協作 WebSocket 權杖，因此不能繞過網頁唯讀介面送出 Yjs 寫入。

## 仍需在正式規模導入前處理

| 優先度 | 項目 | 原因與建議 |
| --- | --- | --- |
| 中 | 協作伺服器多節點擴充 | 目前 LevelDB 持久化適合單一協作容器；若未來改為多個協作節點，需改用 Redis 或資料庫型 Yjs provider，讓不同容器共享同一份文件與 awareness。 |
| 高 | 跨裝置衝突提示 | 目前可避免單一瀏覽器請求亂序，但外部檔案與另一個裝置同時改動時，仍應加入內容雜湊、三方合併與「保留兩份」流程。 |
| 中 | 檔案系統監看與匯入佇列 | 以受控 worker 監看 `workspace-data/documents/`；偵測外部變更後先建立版本，再轉換至 Tiptap JSON，不能直接靜默覆蓋。 |
| 中 | 附件 Markdown 策略 | 為 MinIO 附件加入可攜的相對連結／受保護下載連結；目前 Markdown 只能表達文字連結，不應宣稱可完整匯出附件。 |
| 中 | Markdown 互通性測試 | 建立 GFM fixture 測試，涵蓋表格、巢狀清單、程式碼、連結、特殊字元與 Unicode，避免套件升級時改變輸出。 |
| 低 | Slash 指令與快捷鍵提示 | 使用者體驗可再補齊 `/` 指令選單、搜尋、鍵盤快捷鍵說明與拖放區塊排序。 |

## 資料真實性原則

目前 PostgreSQL 的 Tiptap JSON 是可協作內容的權威資料；`workspace-data/documents/*.md` 是可讀、可備份、可手動調整的交換格式。透過原始碼模式與讀取檔案可安全地將外部修改帶回工作空間，但非 Markdown 原生功能仍以資料庫記錄為準。
