## Design Specificity Verdict

**視覺特異性 3/4；互動特異性 2/4。** 酸性黃綠、深色控制台側欄、等寬 telemetry 字、火箭圖標與「任務控制台」語言，構成非泛用的工程工作區世界觀。功能骨架仍主要是通用的文件樹＋編輯器＋資料庫＋任務＋甘特組合；產品的獨特性多停留在視覺與文案，尚未轉化為更快、更有主軸的工程決策工作流。

**Deterministic scan：** detect.mjs --json app components 回傳 []，共 0 finding／0 rule／0 location；沒有 ignore file。這表示未觸發工具現有的靜態規則，不能等同於無障礙、可用性或資訊架構已通過。

**Visual overlays：** 無可變更 DOM 的瀏覽器工具，無可靠 overlay；未啟動衍生 server，也未變更或登入本機服務。

## Overall Impression

這是有鮮明個性、安全感與工程語境的工作台，而不是無差別 SaaS 皮膚。真正的問題不是功能不足，而是太多功能同時要求注意力；當使用者要找、寫、排程或復原一件事時，主操作面仍不夠安靜、可回復或可被輔助技術完整操作。

## What's Working

1. 火箭控制台的視覺系統有一致、可辨識的產品個性。
2. 回收桶、刪除確認、Markdown 衝突／三方合併與 IndexedDB 離線持久化，建立了高風險操作的安全感。
3. Skip link、可見 focus ring、dialog focus trap／Escape／焦點回復，以及 menu 的方向鍵導覽，提供良好的可及性底座。

## Priority Issues

### [P1] 主工作面缺少單一主角

三欄殼層、右欄訊號、文件工具列、任務表與五欄看板同時競爭注意力。任務應改成表格／看板的單一視圖切換；右欄改為可釘選抽屜；每個模式只保留一個主動作。Suggested command：$impeccable distill、$impeccable layout。

### [P1] 導覽與搜尋無法保留工作上下文

選擇文件、資料庫、模組與設定多只更新 React state，沒有同步 URL；小螢幕又隱藏全域搜尋與右欄「我的工作」。Back／Forward、重整、分享與行動中斷後回復皆不可靠。建立 URL state schema 與全斷點命令面板／搜尋入口。Suggested command：$impeccable harden、$impeccable adapt。

### [P1] 文件工具列是功能目錄而非寫作介面

27–29 個直接動作與 11 個 slash 選項超過工作記憶上限；小螢幕以內嵌捲動壓縮，沒有降低決策量。常駐保留 5–7 個高頻動作，其餘收納至具文字的「更多」與可搜尋選單。Suggested command：$impeccable distill、$impeccable clarify。

### [P1] 核心資料操作缺少完整鍵盤與讀屏路徑

文件／資料庫／看板／甘特重排仰賴 drag；資料庫儲存格控制項沒有可存取名稱；協作儲存／離線狀態不是 live region。需提供上／下移與移至目標的鍵盤路徑、cell label 與 polite/alert status。Suggested command：$impeccable harden。

### [P1] 非同步真實性與錯誤復原不一致

頂欄固定「即時同步中」與固定協作者 01 可違背編輯器真實連線狀態；設定儲存若網路或 JSON 失敗，可能永久 disabled；資料庫 100 列以上未 virtualize。統一真實 mutation／連線狀態、用 try/catch/finally 解鎖表單、虛擬化長表。Suggested command：$impeccable harden、$impeccable optimize。

## Persona Red Flags

**Alex（效率使用者）：** 沒有全域命令面板或搜尋方向鍵結果導覽；大量工具常駐但缺可記憶的快捷路徑；任務缺批次操作。

**Sam（鍵盤／讀屏使用者）：** 對話框與選單基礎很好，但資料表控制項缺名稱，拖曳排序無等效鍵盤操作，儲存失敗不會被朗讀。

**Casey（受干擾的行動使用者）：** 小螢幕沒有搜尋與「我的工作」入口，任務／甘特透過極寬水平捲動存活，沒有適合單手完成「找、確認、更新一件事」的窄版路徑。

## Technical Findings

- **[P1] 危險確認按鈕預設對比約 3.28:1。** 建立 --on-danger 並測試 4.5:1；位置：app/theme.css、ConfirmDialog。
- **[P1] 拖曳排序沒有鍵盤／非拖曳替代。** 新增上移、下移、移入子頁等動作；位置：workspace-shell.tsx、database-view.tsx。
- **[P1] database cell control 缺 accessible name。** 以欄名＋列名組成 aria-label 或 aria-labelledby；位置：database-view.tsx。
- **[P1] editor 儲存、離線、上傳狀態不是 live region。** 使用既有 StatusMessage；位置：collaborative-editor.tsx。
- **[P1] 100 列以上資料庫未 virtualize。** 導入 row windowing、衍生值 memo；位置：database-view.tsx。
- **[P1] Settings 儲存可永久 disabled。** 將 fetch/JSON 包入 try/catch/finally，永遠釋放 saving；位置：settings-panel.tsx。
- **[P2] 行動輸入與小控制項低於 16px／44px 規範。** 對 coarse/mobile 擴大實際 hit area；位置：globals.css、table-editor.css。
- **[P2] 視圖狀態未同步 URL。** 導入 router.replace schema 與 scroll restoration；位置：app/page.tsx、workspace-shell.tsx。
- **[P2] 匯入 polling 沒有 unmount cleanup。** 用 effect cleanup、AbortController、ref 管理 interval；位置：database-view.tsx。
- **[P2] toggle 與配色狀態僅用 CSS class 表示。** 補 aria-pressed、radio semantics；位置：collaborative-editor.tsx、settings-panel.tsx。
- **[P2] custom accent 僅驗證 hex 格式。** 輸入時檢測語意色對比，提供安全還原；位置：theme-toggle.tsx、settings-panel.tsx。

## Systemic Patterns and Minor Observations

- globals.css 與 theme.css 有大量 hex literal／!important，並以 .app \* 做全域 border 覆寫；新元件須加入長 selector 清單才會正確跟隨主題。
- 設定頁將工作空間、同步、外觀、備份、安全、AI、整合放在一個長 form，且沒有 unsaved-change 警告。
- 搜尋沒有 loading、empty、error、stale-request 防護；模板空狀態要求「使用 API 建立」，不是產品使用者的下一步。
- VersionStatus 的更新提示應維持可忽略，而非阻斷式。

## Questions to Consider

1. 「今天最重要的工作」應優先是寫文件、推進任務，還是監測專案風險？這會決定主畫面主角與右欄是否仍常駐。
2. 行動版要追求桌面的全功能複製，還是優先保證「搜尋、查看、更新一項」三個任務？
3. 對高風險資料操作，團隊是否接受先以非拖曳的移動功能取代部分 drag 的便利性，以換取完整鍵盤操作？
